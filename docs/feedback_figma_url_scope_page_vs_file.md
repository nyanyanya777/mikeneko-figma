FigmaのURL(node-id付き)の対象スコープを勝手に1レベルに固定して複数回指摘された。ある回は同一node-id URL(node 123:456="Content"=画面の子)を、一度ファイル/キャンバスページ全体の棚卸しへ**拡大**して叱られ、次に逆に1フレームへ**縮小**して再度叱られた(両方向で誤判定)。

**Why:** node-idはチェーン上の1点を指す座標にすぎず、どの段が意図かを決めない。固定3択(フレーム/ページ/ファイル)には正解が無いことがある——このときの正解は祖先の「設定画面」段で、node自身でもキャンバスページでもファイルでもなかった。動詞(把握して等)の丁寧さでスコープを網羅へ広げる/叱責の反動で真逆へ縮める、が事故の本体。

**How to apply(正本はスキルSOT F-PRC-6):**
- **固定既定を持たない。** スコープは指定node-idの祖先チェーン`ノード自身→属する画面→キャンバスページ→ファイル`から選ぶ1段とみなす。
- **名詞スコープ語だけで機械判定**。動詞はスコープの設定・拡大の根拠にしない。一意に固定する名詞語があれば従い、無ければ(bare「このページ/全部/全体」やnode-id＋動詞のみ)needs inputで祖先チェーンをフレーム名＋各段の中身付きで提示し1問確認。「ページ」をキャンバスページと機械的に同一視しない。
- **判断はユーザー逐語のみ。直前の叱責方向でブレさせない**(過補正で真逆へ振らない)。ゲートは読み取り/把握・委譲・実装のどれにも着手前に先行、確定前にfan-outしない。
- 聞かない例外: 複数URL明示列挙=和集合／クエリ型(使用箇所洗い出し)=ファイル全体／node-id無しファイルURL=ファイル／同一URL確定済み=範囲変更語が無ければ再質問しない。
- 複数の独立作業は同時並行で進めるのを好む(直列で待たせない)。
