# mikeneko-figma — Figma作業のためのClaude Codeスキル群

Figmaのデザイン/デザインシステム作業を Claude Code にやらせるための、自作スキルの一式です。
実務で事故るたびにルールを足してきたもので、大半の条項の背後には実際の失敗があります。

## これは何を解決するか

Figma作業をAIに任せると、だいたい同じところで壊れます。

- デザインシステムに実体があるのに、生のフレームで見た目だけ似せたものを描く
- 検索が空振りしただけで「そんなコンポーネントは存在しない」と断定して新規作成する
- スクリーンショットが一致したことをもって「完成」と報告する
- 「全ページ」と指示されたのに作業中の1ページだけ直して完了扱いにする
- 頼まれていないタブ・列・編集操作を「この種の画面なら普通ある」で勝手に足す
- 画面を「作成方法を選ぶ→入力→確認」のようなウィザードに組み、扱う対象（オブジェクト）が見えなくなる
- 洗い出した概念を全部そのまま画面の箱にして、選択肢の値や操作までオブジェクト扱いする

このスキル群は、そうした失敗を**着手前・実装中・完了前のゲート**として構造で止めることを狙っています。
散文の注意書きではなく、判定可能な条件として書いてあるのが特徴です。

## 設計の土台: OOUI とオントロジー

画面は「何のオブジェクト（名詞）の、どのビュー（一覧か詳細か）か」から起こします（OOUI、F-OOUI-1〜5）。
動詞は画面やステップにせず、ビューの上のアクションにします。

その手前に、オントロジーの層を置いています。

- **オブジェクトの確定**: 洗い出した概念は全件そのまま箱にせず、画面で1件ずつ扱うものだけをオブジェクトにする。値はプロパティへ、操作はアクションへ入れ、対応表で未割当0を確かめる（F-OOUI-8）
- **関係**: オブジェクト同士の参照・多重度（1:1/1:N/N:N）を、画面に出す前に宣言する（F-OOUI-6）
- **操作権限**: ロールごとに「できる／見るだけ／できない」を宣言し、画面の非表示・無効化に反映する（F-OOUI-7）

順序は「オブジェクト → 関係・操作権限 → ビュー」です。
また、画面に置く要素は、依頼者の逐語・要件文書・既存画面のどれかに出典があるものだけに限ります（F-SRC-1）。

## 構成

```
skills/
  mikeneko-figma/          入口。ここで1問だけ判定して、作業スキルを1つだけロードする
    scripts/
      audit-structure.js    生フレーム混入・重複クラスタ・ページ構成の機械監査
      audit-ds-binding.js   色/タイポの変数バインド率の機械監査
  mikeneko-figma-rules/    共通禁止事項（F-*ルール）の唯一の正典（SOT）＋最終ゲート対応表
  figma-ds-edit/           既存のデザイン/DSファイルの編集・レビュー
  figma-component-design/  新規コンポーネントの設計、プロパティ軸の大改修
  figma-design-create/     要件からの新規画面・フロー作成
  figma-e2e-test/          画面の「体験」のE2E検証（設計は直さない、テスト専用）
  figma-modal-open-reorg/  素置きモーダルを「開いた状態」に組み直し、バリアント付きコンポーネントへ格上げ
docs/                      各ルールの根拠。なぜそのルールがあるかの実例つき
```

`skills/` の各 SKILL.md から `docs/` の該当する根拠へリンクしています。
ルールだけ読んでも判断できないので、迷ったら根拠のほうを読んでください。

### 各スキルの中身

- **mikeneko-figma（入口）**: 作業が「既存の編集」「新しい部品」「新しい画面」「体験のテスト」のどれかを1問で判定し、作業スキルを1つだけロードする。共通ルールの併読を必ずさせる。既存画面もDSも無い新規サービスは、別スキル `mikeneko-design-md`（本リポジトリ未収録）へ回す。
- **mikeneko-figma-rules（共通ルールの正典）**: 全スキルに効く F-* ルールの本文はここだけにある。各スキルの最終ゲートとの対応表と、ルールを書き足すときの規約も持つ。
- **figma-ds-edit（既存の編集・レビュー）**: 現物の棚卸し → 計画とゲート → 実装 → 全件レビューの順で進める。テキストスタイル・色変数のバインド、生フレームの部品置き換え、逆差分監査（頼まれていない要素が増えていないか）、OOUI の整合（別オブジェクトの混入やウィザード化をしていないか）、関係・操作権限の整合、重複監査まで見る。
- **figma-component-design（新しい部品）**: Variant・Boolean・Text・Instance Swap のどれを軸にするか、auto-layout の HUG/FILL/FIXED、スロットの出し入れ、変数・スタイルのバインドを決める。軸が直交しているか、全組み合わせのテスト、既存の使用箇所への影響までを完了条件にする。
- **figma-design-create（新しい画面・フロー）**: 要件の確定から始め、作る画面・改修する画面・遷移配線のリストを先に出す。OOUI のビューインベントリ（どのオブジェクトのどのビューか）、オブジェクトの関係と操作権限、ページ構成（1オブジェクト1ページ）を宣言してから作り、最後に宣言と成果物を機械的に突き合わせる。要素の出典（依頼者の逐語・要件文書・既存画面）、既存の姉妹画面との一貫性、プロトタイプの配線までを見る。
- **figma-e2e-test（体験のテスト）**: 利用者の目標を与え、画面に見えるものだけで達成できるかを盲目のウォークスルーで確かめる。詰まった箇所の原因を、UXの欠陥・未配線・文言・状態の欠落・OOUI の退行・ページ構成のどれかに切り分けて報告する。設計は直さず、修正は ds-edit / design-create に渡す。
- **figma-modal-open-reorg（モーダルの整理）**: 素置きされたモーダルを、親画面＋背景の暗幕＋中央ダイアログの「開いた状態」に組み直し、繰り返し出るモーダルはバリアント付きの部品にする。
- **scripts/**: `audit-structure.js` は生フレームの混入・auto-layout・重複クラスタ・ページ所属を、`audit-ds-binding.js` は色とタイポの変数バインドを、Figma 上で機械的に監査する。

### 共通ルール（F-*）の系統

| 系統 | 何を止めるか |
|---|---|
| F-STR | Spacer の空フレーム、auto-layout でないコンテナ、場当たりの線 |
| F-CMP | アイコン未指定のアイコンボタン、部品の手描き偽装、マスター部品の直接編集、強調のための fill/stroke の書き換え、完成フレーム内の部品でないスタイル付き要素、同じ構造の複製放置（2コピー目で部品化）、部品化の機械監査を通さない完了 |
| F-PLC | 根拠の無い置き場所、指定ノード以外への複製、不在の断定と重複作成、1つの機能が複数ページに散ること、配置先ページを事前に特定しない複製、ルールの正典を手順なしに書き換えること |
| F-SRC | 出典の無い要素（依頼者の逐語・要件文書・既存画面の3つだけが出典）、他案件の要素の混入、「良かれ」での追加、明言された要素の削除 |
| F-OOUI | オブジェクトとビューが決まらないまま画面を作ること、ウィザードへの退行、値や操作のオブジェクト化、選択肢の取りこぼし、関係と操作権限の未宣言、概念の棚卸しをそのまま箱にすること |
| F-QLT | AIっぽい過剰な配色、WCAG AA 未満のコントラスト、14px 未満の文字、再着色だけの別案、生の値の直書き、ワイヤー止まり、既存画面との不一致、業界ベンチマークの所見を処分しないままの完了、ビジュアル判定の証跡（完了報告の verdict 行）が無い完了 |
| F-PRC | 合意前のビルド、画像を見られないモデルへの画像再現の委譲、Figma 以外への成果の書き出し、不自然な日本語の文言、全称スコープの縮小、URL・node-id の対象範囲の勝手な固定、デザイン委譲のモデル格下げ、レビュー結果の曖昧な扱い、判断レビューを決定論監査より先に回すこと、受け入れ証拠の欠落、参照UIを見ないままの設計、作業スキルを通さない書き込み |
| F-INT | 空間の指示（余白・揃えなど）をどのノードのどのプロパティか確定しないまま動くこと、レンダリングを自分で見ずに「直った」とすること |

## 使い方

`skills/` 配下を Claude Code のスキルディレクトリ（`~/.claude/skills/`）に置くと、
Figma作業の起点で `mikeneko-figma` が発火します。作業スキルは共通規範 `mikeneko-figma-rules` を併読する前提なので、7ディレクトリをまとめて置いてください。
Figma の MCP サーバーが接続されていることが前提です。
入口の `mikeneko-figma` は既存プロダクトの改修を想定しています。DS も姉妹画面もまだ無い新規サービスのデザインを始める場合は別スキル `mikeneko-design-md` を案内しますが、このリポジトリには含まれていません。
