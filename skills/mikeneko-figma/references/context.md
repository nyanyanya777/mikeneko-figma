# 案件の把握（実物・好みの記録・最初の1画面）

**いつ読むか**: 規模が中・大の作業の最初。依頼者に何か言われて直したあと（好みの記録に足すとき）。委譲のブリーフを書くとき。規模が小のときは、末尾の「規模ごとの量」だけ読めばよい。

[mikeneko-figma](../SKILL.md)（入口）の詳しい手順。対応するルールは F-PRC-13 と F-PRC-14（正典は [mikeneko-figma-rules](../../../skills/mikeneko-figma-rules/SKILL.md)）。

把握するものは3種類あり、取れる時期が違う。全部を着手前に聞き出そうとすると質問が増えるだけで、いちばん効く「好みと禁止」は取れない。

| 種類 | いつ取れるか | 取り方 |
|---|---|---|
| 実物（要件、文言、見本、部品、素材） | 着手前 | 聞くより、見て確かめる |
| 好みと禁止 | 何かを見せたあと | 最初の1画面を早く見せ、言われたことを言葉のまま残す |
| 上の2つの持ち越し | セッションをまたいで | 案件の DESIGN.md に書き、毎回最初に読む |

## 1. 着手前に取るもの（実物）

ここは、各作業スキルの工程0〜2で取るものの一覧で、別の工程ではない（範囲が決まる前に読み始めない＝F-PRC-6）。それぞれに「どこで見たか」（URL、node-id、ファイルと行）を添える。見ていないものを、見たことにしない。Figma 上の見本の計測は承認後に行い（[tone-measure](../../../skills/figma-design-create/references/tone-measure.md) §2）、段階表はそのとき DESIGN.md に足す。

- **何の画面で、誰が何をするためのものか**: 要件の原文（依頼者の逐語、議事録、要件文書）。
- **文言の出どころ**: 原稿、議事録、既存画面。無い語は作らない（F-SRC-1）。
- **見本**: 姉妹画面（TWIN）か、依頼者が名指しした実在プロダクト。濃さ・太さ・線の強さ・余白は実測する（F-QLT-10 → [tone-measure](../../../skills/figma-design-create/references/tone-measure.md)）。
- **使える部品**: DS やキットの棚卸し（→ [inventory](../../../skills/figma-ds-edit/references/inventory.md)）。
- **使える素材**: ロゴ、写真、図。あるものだけを使い、無いものを作って足さない。
- **欠けているもの**: 上で埋まらなかった項目だけを、1回にまとめて聞く。

確かめたことは、DESIGN.md の「案件の実物」に書く（書式は下）。

## 2. 把握できたかを3行で確かめる

要件の原文と見本の所在が分かった時点で、次の3行を依頼者に見せる。工程0で見せる1枚の先頭に置き、同じ往復で見せてよい（質問を増やさない）。直されたら、まだ把握できていないので、直された行に関わる実物を取り直す。

```
作るもの: <何のオブジェクトの、どのビューか。誰が何をするためか>
合わせるもの: <見本（姉妹画面か、名指しされたプロダクト）と、合わせる点>
やらないこと: <好みの記録にある禁止と、今回のスコープ外>
```

これは F-PRC-1（構造の合意）や工程0の宣言の代わりではない。それらの前に、方向が合っているかだけを確かめる。

## 3. 最初の1画面を早く見せる（F-PRC-14）

規模が中・大のとき。好みと禁止は、表や宣言を見せても出てこない。画面を見せると、数分で出てくる。

1. いちばん代表的な1画面を選ぶ（そのプロダクトで利用者がいちばん長く見る画面。迷えば依頼者に1問聞く）。
2. 画面をまたぐ宣言は、全体ぶんを先に出す（オブジェクトの表＝表A、作成フレームリストの名前、ページIA）。ビューごとの詳細（表B以降）、設計マッピング表、承認は、その1画面のぶんだけ先に済ませる。出典（F-SRC-1）と処遇の台帳（F-PRC-12）は、その1画面のぶんも省かない。残りの画面の詳細と承認は、方向を確かめたあとに行う。
3. その1画面を作り、描画を自分で見て、明らかな崩れを直す。
4. **依頼者に見せて、方向を確かめる。** 見せるときに「方向の確認用で、監査と判定はこのあと」と伝える。
5. 言われたことを、好みの記録に足す（下の書式）。却下されたら、残りを作る前にその1画面を直す。スクリプトで組んでいるなら、依頼者が Figma 上で触っていないことを確かめたうえで、スクリプトを直して流し直す（残りの画面でも同じ関数を使うので、キャンバスだけを直さない）。
6. 方向が合ってから、残りの画面の宣言と実装に進む。

**見せ方とフックの関係（未確認）**: F-QLT-9 と F-CMP-7 は Stopフックで強制されていて、書き込んだあとにターンを終えると、verdict の行と run3 を求められる。方向の確認は、ターンを終えずに AskUserQuestion で行う（スクショか、Figma のノードへのリンクを添える）。ターンを終えて見せるしかないときは、その1画面について run3 と判定役を済ませてから見せる。フックの本体はこのリポジトリに無いので、この扱いは共通ルールの文面からの推定。初回に確かめる。

## 4. 好みの記録

依頼者に言われた却下・禁止・好みを、**言われた言葉のまま**残す。自分の言い換えだけを残すと、次に読んだときに元の意図が分からなくなる。

- 1件=1行。日付、依頼者の言葉（かぎかっこで逐語）、何をやめて何にしたか、効く範囲。
- 言葉から読み取った一般則は、逐語のあとに「→」で分けて書く。逐語と解釈を混ぜない。
- 取り消されたら、消さずに「取り消し」と日付を書き足す。
- 前の記録と食い違うことを言われたら、新しいほうに従い、古い行に「上書き」と書く。どちらか分からなければ1問聞く。
- 褒められた点も残す（「これは良い」と言われた見せ方は、次の画面でも使える）。
- 依頼者が言っていないことを書かない（自分の反省や推測は書かない）。

次の画面からは、作る前にこの記録を読み、判定役への入力にも入れる（F-QLT-9）。記録にある禁止に当たる成果物は、他が全部合格でも出さない。

## 5. DESIGN.md の書式

案件のリポジトリ（または作業フォルダ）直下の `DESIGN.md` に、次の3節を置く。`mikeneko-design-md` が作った DESIGN.md があれば、その末尾に足す。DESIGN.md が無ければ、この3節だけのファイルを作る（置き場所が分からなければ依頼者に1問聞く）。成果物は Figma に書き戻す（F-PRC-3）。このファイルは成果物ではなく、作業の控え。

```markdown
## 案件の実物
| 何 | 中身（要約1行） | どこで見たか | 確かめた日 |
|---|---|---|---|
| 要件 | | <ファイルと行／議事録／依頼者の逐語> | |
| 文言の出どころ | | | |
| 見本 | | <URL／fileKey と node-id> | |
| 部品 | | <ライブラリの fileKey。主要な部品のキー> | |
| 素材 | | <ファイル> | |
| 未確認 | <まだ見ていないもの、聞いているもの> | | |

## 見本の段階表
見本: <名前>（<URL／node-id>。測った日）
| 場所 | 見本 | このプロダクト |
|---|---|---|
| 面: アプリ枠／本文／カード | | |
| 線: 構造／表の行／操作部品 | | |
| 文字色: 主／副／補助／選んでいないナビ項目／アイコン | | |
| 文字の太さ: 見出し／数字／本文／表の見出し行／ボタン／バッジ | | |
| 塗り: 主ボタン／進み具合バー／濃いバッジ | | |
| 余白: 行の高さ／操作部品の高さ／カードの内側余白／箱の間隔 | | |

## 好みの記録
- <日付> 「<依頼者の言葉>」 → <何をやめて何にしたか>（効く範囲: <画面／案件全体>）
```

## 6. 持ち越し

- セッションの最初に DESIGN.md を読む。会話が長くなって要約が入ると、途中で決まったことは要約に残った分しか引き継がれない。ファイルに書いたものは落ちない。
- 決まりごとが増えたら、その場で DESIGN.md に足す（セッションの終わりにまとめて書こうとしない）。
- **委譲するときのブリーフ**には、「好みの記録」と、段階表のうち「このプロダクト」の列（どの場所をどの値にするか）を入れる。見本プロダクトの名前と画面は入れない（要素の出典と取り違えさせない＝F-SRC-1・F-PRC-11。`item-provenance-pretool.sh` が止める語を書かない）。ブリーフに DESIGN.md のパスを書いて丸ごと参照させず、必要な行を写す。依頼者の逐語に、止められる語が入っている行は、「→」のあとの解釈だけを写す。
- 判定役には、好みの記録を、宣言（`MAIN:`/`PRIME:`）と同じ扱いで渡す（スクショと数字を先に見てから照合させる）。

## 7. 規模ごとの量

| 段 | 把握するもの |
|---|---|
| 小 | 対象ノードの現物（自分で取ったスクショと構造）と、依頼者の言葉。DESIGN.md があれば「好みの記録」だけ読む。3行の確認と最初の1画面は要らない。却下や好みを言われたときだけ記録に足す（DESIGN.md が無ければ、作ってよいか1問聞く） |
| 中 | この資料の全部（実物、3行の確認、最初の1画面、好みの記録）。新規部品のときは、最初の1画面の代わりに、1つ目の variant を代表の使用箇所に置いて見せる |
| 大 | 中の全部＋各作業スキルの宣言の表。最初の1画面は、領域ごとに1つずつ見せる |
